# Json Input - JSON 输入规范

## 两种输入方式

多数服务命令同时支持 `-json` 和 `-jf`：

| 选项                          | 含义                           | 使用场景                     |
|-------------------------------|--------------------------------|------------------------------|
| `-json <json-string>`         | 直接在命令行中传入 JSON 字符串 | 临时查询、字段较少的操作     |
| `-jf,--json-file <json-file>` | 从 JSON 文件读取输入           | 运维模板、复杂输入、重复操作 |

两个选项最终都会转换为同一个 Java 输入对象。对于复杂结构或需要反复修改的输入，推荐使用 `-jf`。

## JSON 文件要求

`-jf` 读取的文件必须满足以下要求：

- 文件内容必须是严格 JSON，不支持注释和尾随逗号。
- 根节点必须是 JSON 对象。
- 文件应使用 UTF-8 编码。
- 字段名区分大小写，应按照各命令页面中的字段名填写。
- 未在输入类中声明的字段不应加入模板。

## 路径解析

`-jf` 的路径由 Telqos 服务进程解析，不是由 Telnet 客户端解析。

相对路径基于服务进程的工作目录。生产环境建议使用绝对路径，例如：

```text
settingnode -inspect -jf /opt/settingrepo/docs/telqos-manual/zh-CN/json-file/settingnode/inspect.json
```

Windows 环境中的绝对路径应使用正斜杠，或者对反斜杠进行 JSON 转义。

## 公共字段

Setting Repository 的节点类命令通常使用以下公共字段：

| 字段        | 类型         | 说明                               |
|-------------|--------------|------------------------------------|
| `category`  | string       | 设置类别，通常同时也是格式化器类型 |
| `args`      | string array | 用于生成节点标识的格式化参数       |
| `index`     | integer      | 列表节点中的条目索引，从 `0` 开始  |
| `file_path` | string       | Telqos 服务端本地文件路径          |

`category` 与 `args` 共同决定节点标识。执行写操作、删除操作或缓存清理前，必须确认二者指向预期节点。

## 字段命名与类型

JSON 字段名由 Java 输入类中的 `@JSONField` 指定，通常使用小写下划线形式，例如：

| JSON 字段        | Java 字段含义     |
|------------------|-------------------|
| `item_string_id` | 键值对条目 ID     |
| `mek_id`         | 国际化消息 MEK ID |
| `old_index`      | 调整顺序前的索引  |
| `neo_index`      | 调整顺序后的索引  |

数组字段必须使用 JSON 数组，不能使用逗号拼接的字符串。整数索引必须使用 JSON 数字，不能使用带引号的字符串。

## 时间与地区字段

国际化节点使用以下地区字段：

| 字段       | 规则                                        |
|------------|---------------------------------------------|
| `language` | 2 至 3 位字母，例如 `zh`、`en`、`ja`        |
| `country`  | 2 位字母或 3 位数字，例如 `CN`、`JP`、`001` |
| `variant`  | 5 至 8 位字母或数字，可以为空               |

没有地区限定条件时，可以将 `country` 或 `variant` 设置为 `null`。

## 键对象

导航节点中的 `item_key` 和 `parent_item_key` 使用长整型键对象。其 JSON 结构为：

```text
{"long_id": 1}
```

`long_id` 必须是整数，不能使用字符串。

## 文件路径字段

包含文件上传、下载或更新的命令使用 `file_path`：

- 上传命令从 `file_path` 读取服务器本地文件。
- 下载命令将内容写入 `file_path` 指定的服务器本地文件。
- 更新命令从 `file_path` 读取替换内容。

`file_path` 不是客户端文件路径。执行上传前，应确认 Telqos 服务进程拥有源文件读取权限；执行下载或更新前，
应确认目标路径可写，并避免覆盖关键文件。

## JSON 模板目录

全部可直接修改的输入文件位于：

```text
docs/telqos-manual/zh-CN/json-file/
```

目录结构与命令 `IDENTITY` 一致。各命令页面提供对应 JSON 文件的相对链接。

`confext/json-example` 是运行时示例副本。修改节点输入模型后，
应同步更新 `docs/telqos-manual/zh-CN/json-file` 与 `confext/json-example`，避免两套模板不一致。

## 修改后的检查

修改 JSON 后，建议至少完成以下检查：

1. 确认 JSON 可以被标准 JSON 解析器解析。
2. 确认字段名称与命令页面一致。
3. 确认必填字段不为 `null`。
4. 确认 `category` 和 `args` 指向正确的节点。
5. 确认所有服务器本地路径存在且权限正确。
6. 对删除、清空和批量更新操作进行二次确认。

## 常见问题

| 现象                   | 可能原因                                                     |
|------------------------|--------------------------------------------------------------|
| 找不到 JSON 文件       | `-jf` 使用了客户端路径，或相对路径基准不正确                 |
| JSON 解析失败          | 存在注释、尾随逗号、缺少引号或编码错误                       |
| 字段未生效             | 字段名拼写错误，或使用了 Java 字段名而不是 `@JSONField` 名称 |
| 上传文件失败           | `file_path` 不存在，或 Telqos 进程无权读取                   |
| 下载文件失败           | 目标目录不存在，或 Telqos 进程无权写入                       |
| 节点操作结果不符合预期 | `category`、`args` 或列表索引不正确                          |
